# 本地笔记图谱

本地优先的 Markdown 笔记与知识图谱应用。记录项目、人物、技能与学习问题，通过 `[[笔记标题]]` 连接内容，并在图谱中查看关联。

当前桌面发布版本：**1.1.0**。提供 Windows x64 安装版与免安装版。安卓应用仍在开发，不包含在本次发布中。本公开仓库只包含通用示例，不包含用户实际笔记。

## 安装

在本仓库的 [Releases](https://github.com/Zengyi-Xu/local-note-graph/releases) 页面下载：

| 文件 | 用途 |
| --- | --- |
| `Local-Note-Graph-Portable-1.1.0-x64.exe` | 免安装，双击启动 |
| `Local-Note-Graph-Setup-1.1.0-x64.exe` | 安装后从桌面或开始菜单启动 |

安装包尚未提供可信发布者代码签名，Windows 可能显示安全提示。核对下载来源及发布校验值，不要关闭系统安全防护。

免安装不代表笔记保存在 EXE 旁边。仅复制 EXE 到另一台电脑不会带走笔记，迁移前必须导出 JSON。

## 五分钟上手

1. 启动后先阅读通用示例；不需要的示例可以删除。
2. 点击左侧「新建笔记」，填写标题。
3. 切换到「编辑」，输入 Markdown 正文。
4. 切回「预览」，查看排版效果。
5. 新建第二篇笔记，输入 `[[第一篇笔记的标题]]` 建立联系。
6. 切换到「图谱」，查看关联节点。
7. 使用顶部 JSON 导出功能创建第一份备份。

## 笔记管理

左侧提供搜索与分类列表，右侧切换笔记或图谱视图。

- 打开笔记默认进入预览，编辑标签用于修改 Markdown 源码。
- 标题、类型、人物身份、标签都可以在笔记区域修改。
- 编辑修改会写入当前应用的本机活动数据。
- 删除需要确认，当前没有回收站，删除重要笔记前请备份。
- 列表按类型组织，不是磁盘文件夹浏览器，不会自动监视 Markdown 文件夹。

尽量使用不重复的标题。内部链接按标题匹配，重名可能产生歧义；重命名后应检查其他笔记里的引用文字。

## Markdown 写法

```markdown
# 项目计划

## 当前进展

- 完成需求梳理
- 参考 [[相关技能]]

**重点**、*补充说明*、`代码片段`

> 引用或备注

| 项目 | 状态 |
| --- | --- |
| 原型 | 已完成 |

水的化学式：H~2~O
写入噪声：σ~w~
平方：x^2^
```

1.1.0 新增：图谱标签的**交集筛选**（按 `功能:`、`材料:`、`器件:` 前缀分组，同组内取并集、跨组取交集）；多维度节点显示**多色色环**；笔记列表的类型分组可分别折叠；**双向同步**（本地改动自动写回同步文件，文件被外部改动则自动拉入，可随时关闭以切断）；两边同时改动时弹出**冲突对比**，逐条选择保留哪个版本；视图支持**笔记 / 图谱 / 并列**三种布局，笔记视图下编辑区为**左源码、右渲染**分栏。同时修复图谱节点持续漂移导致难以点中的问题，并加入拖动阈值（拖动不再误触打开笔记）。

1.0.2 新增 Typora 风格 `~下标~`、`^上标^`，保留 1.0.1 的 `<sub>`、`<sup>` 支持。`~~文字~~` 仍为删除线。代码段不转换，普通 `σ_w` 也不会自动转换，需要改写为 `σ~w~`。更新源码不会更新旧 EXE，请启动新版；升级不会自动改写已保存笔记。

渲染器不支持任意 HTML，也不能假定兼容所有 Typora、Obsidian 或数学公式插件语法。反馈渲染问题时请提供无个人信息的最小示例。

## 双链与图谱

在正文输入 `[[笔记标题]]`；输入 `[[` 时可以从已有笔记建议中选择目标。

- 预览中的内部链接可打开对应笔记。
- 不存在的目标可以通过提供的创建入口建立笔记。
- 已有笔记之间的引用在图谱中显示为连线。
- 可按类型、人物身份和标签筛选图谱。
- 点击节点打开笔记，双击聚焦或取消聚焦，拖动调整布局。

筛选只改变显示，不删除笔记。图谱表示笔记链接，不是自动生成的知识总结。

## 阅读主题

在预览工具栏选择内置主题，或通过主题导入按钮选择 Typora `.css` 文件。

- CSS 文件需小于 500 KB。
- 当前保存一个自定义主题，再次导入会替换原自定义主题。
- 主题选择与 CSS 保存在本机，不包含在笔记 JSON 备份中。
- 只导入可信 CSS；远程字体、图片等资源可能产生网络访问。

导入的是单个 CSS，不是整个主题文件夹。依赖额外字体、图片、CSS 或 Typora 特有结构的主题，可能需要适配，不能保证完全一致。

## 保存、备份和同步

| 功能 | 实际行为 |
| --- | --- |
| 本地保存 | 活动笔记保存在当前应用的 localStorage |
| 全部 JSON 导出 | 导出全部笔记快照，用于备份和迁移 |
| 单篇 Markdown 导出 | 导出当前笔记正文和部分元数据 |
| 保存到同步文件 | 桌面应用把全部笔记写入选定 JSON |
| 云盘同步 | 外部云盘客户端传输该文件 |
| JSON 导入 | 把文件中的笔记作为新笔记追加 |

**同步 JSON 不是第二套活动数据，也不是双向同步数据库。** 编辑作用于本机数据，外部文件只是快照。程序不会自动读回同步文件，也不会合并另一台设备的修改。

保存提示不能替代独立备份；存储空间不足等异常仍需通过导出和核对内容验证。

### 设置同步文件

1. 在顶部同步相关操作中选择保存文件。
2. 选择云盘实际同步的目录，例如 `笔记备份/notes.json`。
3. 手动保存，确认文件产生且云盘上传成功。
4. 按需开启自动同步，后续修改会触发全部笔记快照写入。
5. 定期另存日期备份，不要只保留一个会不断被覆盖的文件。

写入采用临时文件再替换目标文件，减少半写入风险，但不能防止误删、设备冲突或云盘覆盖。

浏览器版不能调用 Electron 的原生文件写入接口，应使用 JSON 下载；下载不等于持续写入固定同步文件。

### 在另一台设备使用

1. 等待云盘同步完成。
2. 先备份目标设备当前笔记。
3. 通过 JSON 导入读取文件。
4. 核对内容，再开始编辑。

**当前导入是追加，不是覆盖、去重或原样恢复。** 导入会创建新 ID 和时间戳，重复导入可能产生重复笔记。

不要让两台设备同时编辑并自动写入同一个文件。后写入快照可能覆盖另一台的修改，当前没有冲突检测，设备切换需要人工管理。

## 导入与导出

顶部 JSON 导出包含全部笔记，不是当前分类或当前笔记。建议放在备份目录，而不是某个项目子目录。

标题旁的下载按钮导出单篇 `.md`，文件名来自标题，内容包含 Markdown 和部分 frontmatter 元数据。顶部 Markdown 导入入口读取单个文件，支持 `title`、`type`、`grade`、`tags` 等受支持字段。

当前不提供完整 Obsidian Vault、附件文件夹、插件配置或目录树导入。JSON 不会自动打包图片文件及主题资源；引用的资源需要单独备份。

## 数据与隐私

- 浏览器版、桌面版、不同浏览器和用户配置不会自动共享本地数据。
- 不需要账号，应用不提供内置云端笔记服务。
- 清理网站数据、删除应用用户数据或重装系统可能导致笔记丢失。
- JSON 和同步文件是明文，不是加密保险箱，应自行限制访问。
- 外部链接、远程图片、主题资源和云盘可能涉及网络访问。
- 不要把实际笔记、JSON 备份、用户数据目录或签名密钥提交到公开仓库。

升级、清理数据或迁移之前，请先导出并验证备份。

## 常见问题

### 为什么新功能没有出现？

源码更新不会自动更新旧 EXE。下载新版，确认没有从旧快捷方式启动旧程序。

### 为什么同步文件更新了，应用没有更新？

当前同步只向外写快照，需要手动导入。注意追加导入可能重复。

### 为什么换电脑看不到笔记？

程序和笔记数据分开。需要旧设备导出、新设备导入，仅复制 EXE 不够。

### 为什么主题和 Typora 不完全一样？

正文结构与资源加载方式不同。先切回内置主题排查，再检查 CSS 和依赖资源。

### 为什么升级后显示示例？

应用身份或存储键变化可能使用不同的本地数据空间。保留旧版用户数据，从旧版导出再导入新版；当前不保证自动迁移。

## 本地开发与打包

技术栈：React、TypeScript、Vite、Tailwind CSS、Electron。

在仓库根目录执行：

```bash
npm ci
npm run dev
```

打开终端显示的地址。检查与生产构建：

```bash
npm run lint
npm run build
```

Windows 桌面运行及打包：

```bash
npm run desktop:dev
npm run desktop:dist
```

默认产物位于 `release/`。若构建器无法确定 Electron 版本，先检查依赖是否完整安装，不要发布不完整产物。

| 目录 | 用途 |
| --- | --- |
| `src/components/` | 列表、编辑、预览与图谱 |
| `src/hooks/useNotes.ts` | 活动笔记与本地存储 |
| `src/lib/` | Markdown 与文件操作辅助 |
| `electron/` | 桌面窗口和文件接口 |
| `build/` | 应用图标 |
